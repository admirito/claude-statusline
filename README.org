#+TITLE: claude-statusline
#+OPTIONS: toc:nil num:nil

A status line for [[https://claude.com/claude-code][Claude Code]] that fits a lot into a narrow line, and stays
quiet until something needs your attention.

#+begin_example
[alice|Opus 5⡇|Max] main +156/-23 | ⌚15h Ⓐ61m | $4.82 »54% ⧗24%→3h | 312K/1M [####--------32%] ⚡91%⏱53m ↗12K
#+end_example

Everything that can be silent is silent. Rate limit windows past the first
appear only once they constrain you, a cache miss names its cause for five
minutes and then keeps only the count, and the session-mode flags are absent
entirely unless a mode is on. A healthy session is the line above; a session in
trouble says so without you going looking. The one thing that is always on is
the cache countdown, because "can I leave my desk" is asked while everything is
healthy.

The same script also draws the agent panel under the prompt, one row per
background agent, in the same language. See [[*Agent rows][Agent rows]].

* Provenance

Almost none of this shell script is mine. It was written by Claude, in Claude
Code, across a long conversation in which I picked what to display field by
field, pushed back on the recommendations, and reviewed the result. The design
decisions are mine; the code is very largely not. The early commits are
snapshots reconstructed from files I had kept, so they carry no trailer and
should not be read as mine either.

I mention it because you are about to run it, and you should know what you are
reading.

** The second line

A second row appears for one minute at a time, and is absent the rest of the
day. It says the things that are otherwise invisible until they bite:

#+begin_example
⧗ session 12% → 17:05 · weekly 31% → Thu 09:00, pace »54% · cache TTL 1h
↩ back after 47m · ❄ cache went cold, re-caches 192K · session 12% → 17:05 · pace »54%
W weekly limit 60% → Thu 09:00 · pace »108%: runs dry Wed 21:00
✗ cache miss: tools +2/-1 · re-cached 190K
#+end_example

They fire on the session's first render, on a new prompt after ten minutes
away, when a window crosses a band (every 10 up to 50, then every 5), and on a
cache miss. Nothing else, and never for longer than a minute.

* Agent rows

Claude Code lists background agents in a panel under the prompt, and can hand
the drawing of each row to a command. This script is that command too. A row
says what the default one leaves out, in the main line's language, and every
cell has a fixed width so the panel reads as a table (the =○= and the tree
lines are Claude Code's own):

#+begin_example
○ [Haiku 4.5⡇|Explore]  ⌚3m  ▃▅▃▁█▇▇▄▄▄ $0.08  ⚒23      61K·39% ⚡5m      │ +1✗ Find where tokens refresh · Grep refreshToken
○ [Opus 5.5⣿|reviewer]  ⌚25m ▁▁▁▁▁▁▁ 2m $3.10  ⚒41     712K·74% ⚡3m      │ ↗48K ⟲2 +3▁ @reviewer Review the payments module · Bash go test -race ./pay/...
○ [Sonnet 5⡆]           ⌚7m  ▁▁▁▁▁▃█▂▇▆ $1.20  ⚒30       88K·9% ⚡5m      │ ⎇+12/-3↑2 #142⋯ @scout Refactor the cache · Edit cache.go
○ [Opus 5.5⡇|⋔fork]     ⌚2m  ▁▁▁▁█▃▆▃▃▃ $0.95  ⚒4   ⋔366+5K·38% ⚡5m      │ Try the other fix · Edit lock.go

* Requirements

- =bash= 3.2 or newer. macOS ships 3.2 as =/bin/bash=; the script stays inside
  that dialect deliberately.
- =jq=
- =git=, optional. Without it the branch segment reads =no-git=.
- Claude Code 2.1.251 or newer for the cache and spend-limit fields, 2.1.260
  or newer for miss causes. Older versions render everything else and simply
  omit those.
- For the agent rows, a Claude Code whose =subagentStatusLine= sends each
  agent's model and effort: 2.1.214 or newer. =gh=, optional, for the pull
  request of an agent working in a worktree of its own.

* Install

#+begin_src sh
git clone https://github.com/admirito/claude-statusline ~/src/claude-statusline
ln -s ~/src/claude-statusline/statusline.sh ~/.claude/statusline.sh
#+end_src

Then in =~/.claude/settings.json=:

#+begin_src json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "refreshInterval": 30
  }
}
#+end_src

For the agent rows, add the same script as the =subagentStatusLine=:

#+begin_src json
{
  "subagentStatusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh"
  }
}
#+end_src

=refreshInterval= is optional but recommended. Claude Code re-renders on session
events and schedules a wake-up when a rate limit window resets or the cache
expires, so most of the line is live without it. The countdowns are not: they
matter while you are idle, which is exactly when no event fires.

* What it reads, and what it writes

Beyond the JSON payload on stdin, the main line reads up to six files, all
read-only:

| File                                  | For                                        |
|---------------------------------------+--------------------------------------------|
| =~/.claude/.credentials.json=          | =subscriptionType=, to label the plan       |
| =~/.claude.json=                       | email, billing type, legacy auto-compact setting |
| =~/.claude/settings.json= and project settings | the auto-compact setting            |
| managed settings                      | the same, if an administrator set one: =/etc/claude-code/= on Linux, =/Library/Application Support/ClaudeCode/= on macOS, with any =managed-settings.d/= drop-ins |

It touches your credentials file because that is the only place the plan tier is
recorded, and it takes exactly one string from it. Nothing leaves the machine
and the main line makes no network call. If you would rather it did not, delete
=~/.claude/.credentials.json= from the =CFG= list near the top of the account
block; the plan badge then falls back to billing type, which cannot tell Pro
from Max.

The agent rows read, also read-only: the files Claude Code keeps for each
agent beside the session transcript, a small metadata file and the agent's own
transcript, which is read incrementally, only what was added since the last
run; the agent definitions in =~/.claude/agents/= and the project's
=.claude/agents/=, for an agent type's colour; the settings files above,
without the credentials, for auto-compact and the =modelPricing= table an
administrator may set; and, for an agent working in a worktree of its own, a
few =git= commands in that worktree. They make the script's only network call:
=gh pr view=, for such an agent once its branch is on =origin=, run detached,
at most once a minute per branch, and only if =gh= is installed. Set
=AG_PR_EVERY= to 0 to turn it off.

The main line writes one file: a small state file named after the session id,
under =$XDG_RUNTIME_DIR= (or =$TMPDIR=, or =/tmp=) in a
=claude-statusline-<uid>= directory of its own. It holds recent cache misses
(Claude Code reports only the latest one's cause, and this is how the line can
show the last five minutes of them), what the previous render saw, and any
second-line brief still inside its minute. It is read once and written once per
render, and only when something in it changed. If the directory cannot be
written the script carries on without it, and the second line simply never
appears.

The agent rows keep their own file beside it, the same name with =.agents=
added, holding what each agent's transcript has said so far and when its state
last changed. It is rewritten on every run and holds only the agents on screen.
A pull request lookup leaves a one-line =.pr.<branch>= file next to it.

* Configuration

There is no config file. The knobs are constants in the script: the colour
palette, =BRANCH_MAX= for branch name shortening, the threshold tables in
=limit_colour= and =context_colour=, and for the agent rows the =AG_= constants
at the top of their section, such as =AG_BAR= for the seconds each sparkline
bar covers, =AG_QUIET= for when a working agent reads as quiet, and
=AG_PR_EVERY= for the pull request lookup.
